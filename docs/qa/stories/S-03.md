## 1. Requirement & Acceptance Criteria

### Acceptance Criteria
* **AC1**: Hệ thống thiết lập ma trận phân quyền 3 vai trò độc lập:
  * `ADMIN`: Quản trị viên cao nhất, có toàn quyền trên mọi trạm sạc, trụ sạc, người dùng và ví tiền.
  * `OPERATOR`: Đơn vị vận hành CPO, chỉ được quyền thêm, sửa, xóa và theo dõi các trạm sạc và trụ sạc thuộc quyền sở hữu của mình (`operator_id == current_user.id`).
  * `CUSTOMER`: Tài xế sạc xe, chỉ có quyền xem danh sách trạm công khai, thực hiện phiên sạc và quản lý số dư ví của chính mình.
* **AC2**: Mọi yêu cầu gọi đến các API quản trị bắt buộc phải truyền mã JWT hợp lệ; hệ thống ném mã lỗi HTTP 401 Unauthorized nếu thiếu token hoặc token hết hạn.
* **AC3**: Khi người dùng thuộc vai trò `CUSTOMER` cố tình gọi các API quản trị trạm hoặc API phân tích AI, hệ thống ném lỗi HTTP 403 Forbidden.
* **AC4 (Chống leo quyền ngang - IDOR Protection)**: CPO A tuyệt đối không được phép chỉnh sửa, cập nhật trạng thái hoặc xóa trạm sạc/trụ sạc thuộc quyền quản lý của CPO B; hệ thống ném lỗi HTTP 403 Forbidden.

### Non-functional Requirements
* Thời gian kiểm tra phân quyền tại Middleware / Dependency dưới 5ms.
